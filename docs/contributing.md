# Contribuer au projet

## Avant de contribuer

1. Lire la documentation principale
2. Lire la documentation fonctionnelle
3. Vérifier la compatibilité des changements avec le modèle local-first
4. Éviter toute logique de paiement automatique non confirmée

## Bonnes pratiques

- Garder les changements précis
- Ajouter les sous-fonctions documentées
- Mettre à jour les MD de contexte
- Tester le build avant validation

## Propositions acceptées

- Améliorations de la gestion locale
- Ajouts de pages commerciales utiles
- Exports / QR / relances / analytics
- Documentation et tests

## Propositions à éviter

- Webhook d’initiation automatique sans consentement explicite
- Logiciel qui simule des confirmations fournisseur sans callback officiel
- Déploiement public sans HTTPS et sécurité renforcée
